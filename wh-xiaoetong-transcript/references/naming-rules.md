# 命名铁律（真实标题优先，推断名强制标注）

> 来源：52 节更名事故（2026-09-01）——凭印象起名【2025.9.7 浪前重聚及前哨站开营】，误导用户两天后更改为真实课程名【52.2026.8.22 学会低着头做人】。

---

## 一、命名分级

| 标题来源 | 可信度 | 命名方式 |
|---------|--------|---------|
| 用户给的播放页标题（document.title） | 高 | `{序号}.{YYYY.M.D}-{标题去省略号}` |
| 用户口述标题 | 高 | 同上 |
| 转写内容推断 + m3u8 转码时间 | 中 | `{YYYY.M.D}-{主题推断}-【待核对】` |
| 只有 m3u8 无任何标题 | 低 | 同推断名，交付时明确请用户补真实标题 |

## 二、格式规范

- 文件名：`{序号}.{YYYY.M.D}-{标题}.md`（/`.mp4`）
- 分隔符：点 `.` 连接序号和日期，连字符 `-` 连接标题
- 空格：标题内不保留多余空格（`分享47天减重30斤的全流程` 而非 `分享 47 天减重 30 斤的全流程`）
- 省略号：用户标题结尾的 `…` 删除（如有补全内容，用户会给全）
- 同一节课三个位置必须同名：
  - `downloads/{标题}.mp4`
  - `transcripts/{标题}.md`
  - 桌面 `<YOUR_DESKTOP>\{标题}-逐字稿.md`

## 三、推断名规范

当没有真实标题时：
1. 从转写内容提取主题关键词（如"AI 学习范式""开营导学""减重全流程"）
2. 从 m3u8 `#EXT-X-PROGRAM-DATE-TIME` 或 URL 时间戳取日期
3. 命名 `{YYYY.M.D}-{主题}-【待核对】.md`
4. 交付时**明确告知**：这是推断名，不是平台真实标题；用户给真实标题后 30 秒改名

## 四、改名流程（R21 铁律）

改名前必须：
1. 归档旧文件到 `<YOUR_ARCHIVE_DIR>\{日期}-逐字稿更名-{节号}`
2. 三个位置（downloads/transcripts/桌面）全部改名
3. 逐字稿**内部标题**同步改（markdown H1）
4. 更新 README【已验证】章节 + memory
5. Read 回读验证：新标题正确、简体保持、旧名无残留

## 五、实战教训

- **52 节**：文件名【2025.9.7 浪前重聚】是早期凭印象起的，非平台标题；用户确认真实课程名【52.2026.8.22 学会低着头做人】后统一更正（归档 + 三位置改名 + 内部标题 + 文档同步）
- **51 节**：先用推断名【2026.8.17-AI学习范式与开营导学-【待核对】】交付，用户给真实标题【51.2026.8.17 分享一个自用的用AI完成学习的流程】后 30 秒改名——推断主题方向对（AI 学习），只是缺序号和精确措辞
- **53 节**：用户直接给真实标题（带省略号），省略号删除后命名，一次到位

## 六、反模式

| 反模式 | 后果 | 正确做法 |
|--------|------|---------|
| 凭印象起名不核对 | 52 节事故：误导两天 | 真实标题优先 |
| 推断名不带【待核对】 | 用户误以为是真实标题 | 强制标注 |
| 只改文件名不改内部标题 | 打开文档标题还是旧名 | 三个位置全改 |
| 改名前不归档 | 改错无法回退 | 先归档再改 |
